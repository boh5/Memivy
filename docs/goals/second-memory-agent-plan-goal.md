# 第二 Memory Agent 与统一输入：实施计划及验收标准

状态：计划独立评审及修订复审已通过。本文只定义目标与完成条件；授权、实施过程及实际验收状态见 [progress](second-memory-agent-progress.md)，不能以某一步完成代替全部验收。

现有基础：[产品要求](../../PRD.md)、[技术边界](../../TECH_STACK.md)、[开发与验收记录](../../DEVELOPMENT_PLAN.md)。下文核心文件路径相对 `crates/memivy-core/src/`。

## 1. 目标与范围

用户直接表达想法、提出问题、继续讨论；Memivy 主动联系已有记忆，并把新的想法、事实和决定接续到记忆中。用户不必管理上下文，也不必在聊完后手动保存结论。

本轮交付：自然聊天 Agent、全局相关记忆、自动记忆维护、长对话、流式输出、续聊建议，以及主窗口／桌面快捷窗的统一输入和续聊语音。先完成 Agent，再合并现有“记一下／问一问”入口。

保留现有视觉语言、记忆编辑器、资料库、检索引擎、语音引擎和模型设置基础。语音仍按现有方式开始／停止录音，停止只结束转写；用户通过发送按钮或 Command+Enter 提交，Enter 换行。此次不做停顿检测自动发送或新的语音按键方案。

不增加独立用户画像、常驻约定配置、单条记忆禁止 AI 使用、检索范围管理界面、通用 Agent 框架、多 Agent 产品、云服务或新 MCP 工具。专题和指定材料提供讨论重点；所有正常活动记忆仍可被关联。回收站和已永久删除内容遵循既有删除规则。

本计划落实本次讨论已确认的调整，取代本轮范围内的旧约束：强制三段答案、讨论必须手动确认后才能形成记忆、专题聊天仅检索成员、Agent 不能回读相关历史。原有历史验收记录保留；独立的单篇清理预览和手动编辑功能不借此重做。

## 2. 用户行为合同

### 2.1 输入与会话

- 同一个输入框接受文字和语音，不先选择记录／提问模式。表达可以同时包含想法和问题，由同一个 Agent 处理，不再增加前置意图分类模型。
- 纯记录：保存并给简短回执，不自动输出长篇分析或追问。纯问题：结合记忆回答，问题本身不自动变成一条事实记忆。混合表达：保留新想法，同时回答。
- 当前会话中的输入继续当前会话。全局快捷入口恢复最近的快捷会话并显示最近交流；没有会话时新建。保留显式“新讨论”，不按闲置时长暗中切断会话。用户可直接换话题，旧主题不限制全局记忆。
- 从记忆或专题进入，按现有入口创建相应讨论；主窗口与快捷窗交接传递同一会话 ID。全局讨论中可以添加记忆，后续每轮也可以增减指定材料。
- 移除材料只停止其优先带入，不能声称抹去了已经发生的讨论。专题移除后保留会话、草稿及记忆，显示原专题已不可用，不再向该专题加入新记忆。
- 快捷窗中，纯记录成功后沿用普通捕捉的收起行为；固定状态继续留待输入。包含问题时显示回答，用户主动收起后任务可继续。原话仅落盘但整理未完成时，不显示“记忆已更新”。

### 2.2 记忆主动进入上下文

每个新的实质问题在首次模型调用前，使用当前消息、近期讨论意图和指定材料信息，通过现有统一搜索准备全局相关记忆；“写短一点”等单纯变换已有回答的请求可复用已有上下文。Agent 仍能改查、补查，不把第一批结果当成全部记忆。

| 入口 | 首次调用前的内容 |
| --- | --- |
| 全局讨论 | 近期完整对话、必要的早期摘要、全局相关记忆 |
| 指定一条或多条记忆 | 以上内容，加上指定记忆优先；短文全文，长文相关片段 |
| 专题讨论 | 以上内容，加上专题名称／说明、有界目录和相关成员内容；补充专题外相关记忆 |

所有内容共享一个输入预算，给本轮工具结果和回答预留空间。指定材料不能挤掉全部全局补充；超出预算必须标记“片段／目录未完整”，附稳定 ID 和继续读取位置。目录、搜索命中和实际读到的正文分别记录，目录不能冒充引用证据。

普通搜索面向活动记忆的当前正文；追溯过去时，Agent 按记忆 ID 读取相关历史及来源，标明当时状态，不把历史自动覆盖为当前认识。当前正文应保留有价值的变化原因，不能以“历史里还有”为由删掉关键条件。

### 2.3 自动维护与来源

- 原始用户表达先作为会话数据在本地持久化，再开始模型处理。会话原文与整理后的记忆分开保存；压缩摘要、纯问题、一般操作指令不自动进入正式记忆检索。
- 用户的新想法、经历、偏好、条件和决定，由 Agent 新建或更新记忆，不要求逐次确认。“考虑／假设”“已决定”“已执行”保持区别；第三方观点及 AI 建议不能变成用户既定事实。
- 不等讨论结束才维护记忆；一轮中需要时即可写入。暂停遵循用户表达的范围：“这轮别记”只暂停本轮；“接下来先别记”暂停当前会话后续维护，直到用户明确恢复。会话原文仍保存，不改变全局记忆可读性。
- 专题中创建的新记忆加入当前专题；更新已有记忆保留原有成员关系，也允许更新专题外的相关记忆。
- 每次修改关联原话、会话／消息、执行者和版本；只有实际记忆写入依据的用户原话才进入独立来源归档，不额外创建一条当前记忆或整理任务。删除会话仍保留已形成的记忆、原话来源、版本及回执，原会话链接显示不可用；不能把 AI 整理后的正文标成用户已逐字审核。实际写入成功才发回执。
- 写入正文逐项绑定支持该项的原话片段，核心核对来源与逐字引用；未改的完整行继承旧来源，改写旧内容可引用目标当前版本。不能附一组笼统来源后自由加入无绑定段落。结构核验不代替真实模型对事实、否定和状态的语义验收。
- 同轮多条修改汇总为“已更新 N 条”，可展开差异、撤销本次。中途失败时只汇总已提交的修改，不声称整轮全部成功。
- 保留低频手动保存文字的能力，复用编辑器与新的核心写入事务；取消每条回答自动附带的结论审核／融合流程。

### 2.4 回答与持续讨论

回答采用自然 Markdown 流式文本，不再强制“回忆／分析／结论”协议。实际使用的记忆提供可点击引用，引用绑定读到的版本和区间；工具进度、写入回执、续聊建议与正文分开。

用户提问／讨论的完整回答后提供 2—3 条相关续聊建议，点击发送显示出的完整文字，不能替用户宣布尚未作出的决定。已有草稿不得被覆盖；建议生成失败不改变回答和写入的完成状态。纯记录回执不强制附带建议。

长对话按预算管理：先收起可回读的旧工具正文，再压缩较早对话，保留近期完整消息及工具调用／结果配对。摘要记住条件、数字、否定、未决问题和决定变化，并记录覆盖到哪条消息；原文可分页回读。用户纠正或撤销后，旧摘要不能继续把被否决的信息当成当前结论。

## 3. 架构与彻底重构边界

继续使用现有 Rust 核心与 SQLite；只扩展必要的数据字段、工具和事件，不另建记忆库、任务调度平台或 Agent SDK。

| 职责 | 复用位置及本轮改造 |
| --- | --- |
| 界面／原生宿主 | `src/workspace/` 与 `src-tauri/src/workspace.rs`：提交输入、保存草稿、展示增量结果、管理现有任务与窗口交接；不在 UI 实现检索或记忆写入规则 |
| 讨论执行 | `memory/discussion.rs`、`memory/agent.rs`：组织上下文、调用模型、分发工具、处理预算／取消／续聊；复用一个循环，不用固定分类模型加第二个整理 Agent |
| 模型传输 | `model.rs`、`model/tools.rs`：支持流式文本及工具参数增量，参数完整且校验通过才执行；不在传输层决定记忆语义 |
| 记忆核心 | `memory/search.rs`、`records.rs`、`conversations.rs` 等：唯一搜索入口、原话／会话保存、版本、来源、写入事务和撤销；工具不能绕过 MemoryStore |

内部工具只覆盖实际需要：列出记忆、搜索、分段读取当前记忆／历史来源、回读会话、新建／更新记忆、撤销本次修改。工具目录不暴露为新增 MCP 能力；MCP 仍只有显式 capture 和 search。

同一次输入只有一条记忆维护路径。聊天写入在核心事务中完成原话关联、正文变化、必要的专题成员关系与回执，不再排入旧后台整理器二次写入。独立显式 capture 的立即保存能力保留，其维护复用相同的记忆工具及校验；不保留第二套重复的维护决策／终结协议。

必须直接替换并删除本轮废弃的运行路径：

- 固定检索词规划 → 固定 RAG 回答，以及模型能力不足时回退到该流程。
- 强制 `answer` 工具和 `recollections/ideas/conclusion` 输出、相应旧解析器和展示分支。
- 按条数／字符截断代替会话压缩、专题硬过滤、指定 ID 必须先搜索才能读的限制。
- 旧“讨论只读 → 结论审核 → 独立融合保存”依赖链、输入模式驱动的两条对话链路，以及由此失去用途的接口／类型／配置。

不保留运行时双格式兼容、旧协议适配器、开关切回旧 Agent 或失败后换旧路径。已有会话使用现存的正文、来源和版本读取，不继续解析旧结构化答案列；必要 schema 变更走既有数据库机制，保留用户数据，不以删库换取重构。隔离的历史 prototype 不作为正式产品的备用运行路径。

完整 Agent 要求模型通过流式文本和多轮工具能力验证。不满足时明确标出不支持、停止 Agent 执行；原话仍保存，独立的本地编辑、关键词搜索和 MCP capture 继续可用。不得偷偷换模型或退回旧问答流程。

### 3.1 执行、重试和撤销

- 原话保存、工具执行、记忆提交、回答完成分别持久化。一次用户提交对应一个稳定的逻辑输入 ID、一份用户原话；网络重送和失败重试沿用该 ID，模型执行可有新的 attempt。沿现有任务记录扩展，不增加通用事件平台。
- 写入操作 ID 与参数在执行前确定；提交结果与回执一同落库。新 attempt 从同一逻辑输入最后持久化的工具边界恢复，复用已提交结果；不能把重试当成新问题从头规划、换操作 ID 重做成功的修改。新的用户主动提交才是新的逻辑输入。
- 同一逻辑输入只有一个活动 attempt。工具提交及正文状态更新都校验当前 attempt 和取消状态；被替代／已取消 attempt 的迟到结果不得产生新写入或覆盖当前结果。
- 更新校验读到的当前版本和活动编辑草稿。发生冲突不覆盖用户修改，保留本次表达并显示该条更新未完成。
- 修改立即进入当前正文和关键词索引，本轮直接获得新版本；不能等待向量更新后才看见。先读 v1 再写 v2 不得导致本轮合法的 v1 引用失效。
- 整次撤销先校验全部已提交修改的版本和草稿，再原子撤销正文及成员关系；任一冲突则整次不撤销，并列出冲突项。撤销结果进入后续上下文，不能下一轮自行写回。
- 取消停止新工具执行，保留已完成写入及回执；已显示正文保留并标记未完成。重启后恢复最后持久化的正文／工具状态并标记中断，不伪装成完成，不在用户已取消后自动续跑。

## 4. 实施顺序

1. **协议与存储闭环**：先用当前配置的真实模型验证流式多轮工具；确定内部上下文预算及执行上限。替换旧协议，补齐输入／操作持久化、记忆工具、引用和撤销。成功运行“一轮同时记与答”和断线重试夹具。
2. **上下文与自然讨论**：接入首轮全局记忆、指定材料、专题焦点、历史读取、会话压缩、流式正文及续聊建议，跑通下面的语义场景。
3. **统一入口与原生闭环**：合并输入模式，增加全局添加记忆和续聊语音，统一草稿与会话交接，保留现有键盘／录音操作和视觉语言，完成原生验收。
4. **收尾**：独立代码 Review → Fix → Review；同步 `PRD.md`、`TECH_STACK.md`、`AGENTS.md` 中被本计划替换的现行描述，在 `DEVELOPMENT_PLAN.md` 记录实际证据，保留历史验收。不得只完成前两步就宣称本目标完成。

## 5. 验收：全部满足才算完成

### 5.1 行为验收表

使用隔离的合成资料库，预先固定每个场景的输入、已有记忆及预期事实。对照数据库、工具记录和界面判断；模型文本不要求逐字相同；场景质量通过要求表中的事实、状态与写入效果一致。模型质量结果与工程完成条件按本节下方的用户责任边界分别判定。

| ID | 操作／场景 | 通过条件 |
| --- | --- | --- |
| A01 | 无模式选择地输入纯记录、纯问题、混合表达 | 三者均走同一 Agent；纯记录形成记忆及简短回执；只问已有信息不新增事实记忆；混合表达同时保留新想法并回答。全程无必需的保存结论确认 |
| A02 | 模型请求前断网；提交表达后退出并重开 | 原话逐字保留、输入不丢，状态明确是待处理／失败；恢复后可重试，完成一次预期写入；失败时没有“目标记忆已更新”的成功回执 |
| A03 | 只指定《新产品》，全局另有《每周仅 10 小时》《预算 5000 元》；询问可行性 | 首次调用前包含相关全局依据，回答实际使用两项约束，引用可打开；同场景从专题进入也不能漏掉专题外约束；后续新增限制触发补查 |
| A04 | 添加／移除指定材料；专题目录超过输入预算；所需条件位于长文末尾 | 材料支持中途添加；移除后不再优先带入；目录标明未完整；工具可分页列出、分段读至末尾并找到条件；不以目录标题代替正文证据；总输入保持在声明预算内 |
| A05 | 依次表达“考虑收费”“决定收费”“尚未上线”；另给第三方观点和 AI 自己的建议 | 记忆保留考虑、决定、执行状态和来源；不能写成已上线，不能把第三方／AI 观点变成用户决定；后续纠正同时影响记忆和回答 |
| A06 | 分别说“这轮别记”和“接下来先别记”，随后继续讨论 | 两者均保留会话原文及全局读取；前者仅本轮不写，下一轮恢复正常判断；后者在当前会话中持续不写，直到用户明确恢复 |
| A07 | 在专题中产生新想法，并修正已有的专题外计划 | 新记忆加入当前专题；专题外计划可更新且原成员关系保持；同次输入没有再被后台整理器重复写入；移除专题不删除会话或记忆 |
| A08 | 当前决定已改变，询问“以前为何暂停” | Agent 回读相关历史／来源，回答保留当时原因和时间，区分过去与现在；当前记忆仍含有价值的变化原因；不是把全部归档重新加入普通搜索 |
| A09 | 强制触发真实压缩，早期内容含数字、否定、未决方案；随后追问及纠正 | 压缩确实发生且记录覆盖位置；答案保留预设条件，必要时可回读早期原文；纠正后的回答不再使用失效结论；摘要本身不变成正式记忆 |
| A10 | 一轮修改两条记忆及成员关系，随后整次撤销；再制造后续人工编辑冲突 | 无冲突时完整恢复所有效果、保留原话和版本；有冲突时整次不写并显示冲突项；后续对话承认撤销，不自动重做 |
| A11 | 第一条写入已提交但未送达回执时断开，以新 attempt 重试；再送达旧 attempt 结果，并模拟第二条写入失败 | 同一逻辑输入只有一份用户消息，已成功的记忆修改和回执均不重复；新 attempt 复用已提交结果，旧 attempt 迟到不能提交；第二条失败保留第一条成功且准确显示部分完成；过期版本／活动草稿不会被覆盖 |
